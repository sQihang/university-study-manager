# 文件录入与归档

本流程用于整理一批新资料。先看[工作区](workspace-workflows.md)定位规则、工作区根目录的 `归档说明.md`，再按[文件管理](file-management.md)判断目录与命名。以用户一人的学业资料为中心；名单或合照中出现他人，不等于需要为他人建立档案。

## 每批操作清单

- [ ] 确认工作区：沿用本任务已指定位置；若用户未给出，仅递归扫描当前项目中的 `工作区.yaml`。一个候选直接使用，多个请用户选，零个询问用户放在哪里或是否新建；新建位置必须由用户指定并运行初始化脚本。
- [ ] 运行初始化脚本检查已有工作区，补齐 `00-待整理` 与 `归档说明.md`；不迁移旧结构。归档前读 `归档说明.md` 的一般分类及用户特殊规则，本次用户新指示优先。
- [ ] 确认来源：用户指定文件夹就按指定范围；否则扫描 `00-待整理`。先列名称、目录、扩展名、大小；识别资料组、冗余层级、模糊名称、重复与潜在版本。已有本地阅读授权且命名或归属必须核实时，只读必要标题、首页或相关段落；不重复阅读同类型材料。
- [ ] 判断目标：保留有意义的学期、课程和用户自定义用途边界；单份资料直接放入适当分类，不制造单文件目录链；多份明确相关资料才建事项文件夹。按命名规则保留文号、附件序号、修订年份、学期及真实版本。未知主题保持原名并标为待确认，不把同批导入当成同一事项。
- [ ] 只在当前或明确长期功能需要时决定生成机读成果。直接可读源可用 `ReadableSource`；需要转换用 `Processed`；其他用 `ArchiveOnly`。PDF 先检查文字层，必要时 OCR；复杂表格保留静态结构。
- [ ] 一次集中展示简短方案：问题项在前，能确定的在后；每组写一次来源、工作区及归档根路径，表内用相对路径。列出原名、目标名、理由、操作及待确认项。用户可整体确认或逐项修改，按最后确认的方案执行；已有确认不重复要求两轮。外部上传仍需独立授权。
- [ ] 调用 `archive-document.ps1` 复制、比对指纹并登记 `_来源.json`。默认 `00-待整理` 内来源使用 `-MoveInboxSource`，仅在复制与登记成功后移走；显式指定的其他文件夹不使用该开关，保留原件。失败、疑点或权限问题时来源保留；不得删除外部源文件。
- [ ] 核对实际文件、重名、层级、来源记录与机读成果质量；失败不报告完成。若分类或将来归档规则变化，概括更新 `归档说明.md`，不记每份文件对应路径；提醒用户阅读并可提出修改。本批明细留在 `_来源.json`。
- [ ] 按下方模板汇报：先展示问题和待确认，再展示已完成；共同路径只写一次，表格简洁。移走、保留、提取、失败和规则变化分别写明。
- [ ] 本批生成机读成果时，按入口的完成检查合并提示用户对照原件核验，列出本次关键内容和原文位置；仅归档不追加正文核验要求。

## 归档与提取判断

当前功能明确需要、长期核心功能依赖或持续累计的个人学业记录，才默认生成机读成果。课表、成绩、培养方案和当前有效核心政策通常符合；凭证、临时活动及一次性操作材料通常只归档，后续需要时再提取。已有 UTF-8 MD、CSV、JSON、TXT 或静态 HTML 且确需读取时，使用 `ReadableSource`，不制造副本。简单表格可用 CSV；合并单元格、多级表头或跨页表格保留静态 HTML 结构，不用展平文本猜测。

政策正文与附件、同一证明的多页文件可视作一组；普通同批下载仅是弱线索。“附件一”“正文”“报名表”等先通过用户说明、原目录和可授权读取的关联标题判断。若无法确认，在报告问题区列出，保留原名等待用户说明。用户明确要求先归档时才使用其确认的待归类位置，不编造主题。

## 归档前方案示例

来源：`D:\下载\本次资料`　工作区：`D:\学业\工作区`　下表目标均相对 `01-资料库/`。共 6 份，2 项需确认；建议只归档 4 份、处理 2 份。

**需你确认**

|状态|原文件或组|建议目标|原因 / 问题|
|---|---|---|---|
|❓|`附件一.pdf`|暂不确定|缺少所属通知；请说明主题，或允许只读标题。|
|❓|`活动证明（1）.jpg`、`活动证明（2）.jpg`|`03-学期资料/2026-2027-1/综测材料/活动证明－第01页.jpg` 等|页序可确认，学期和综测用途请确认。|

**可直接按此整理**

|状态|原文件或组|建议目标|处理及理由|
|---|---|---|---|
|✅|`课表 (1).xlsx`|`03-学期资料/2026-2027-1/01-课程/课表.xlsx`|清理下载副本后缀；归档并作为可读来源。|
|✅|`奖学金办法2026修订.pdf`|`01-学校资料/奖学金办法－2026修订.pdf`|保留真实修订年；只归档。|

请回复“按表整理”，或直接指出要改的行。这里的 ✅ 表示方案可确定，不表示尚未执行的操作已完成。

## 质量与恢复

脚本成功仅说明生成文件。处理后先读质量报告，再核对所需结果的乱码、缺页、标题、表格、公式、数值及日期；问题醒目列明受影响结论。核心缺失或大面积错误不登记为可用成果。乱码先核对编码、服务返回文件及处理路径；重试须有条件变化，同因失败不反复提交云任务。

原件到机读成果的提取质量，与机读成果到看板、提要等衍生输出的一致性分别检查。两份衍生成果相同，不能证明首次提取忠实于原件；已有质量报告和来源记录直接复用，不新增账本或默认要求再跑一轮 AI 复核。

同源坏成果用 `repair-artifact.ps1`：新结果在临时区生成并核验，再原子替换成果和记录；这不改变政策版本。中断保留当前输出和状态，重启先检查已有成果；来源账本仅在全部复制和核验完成后写入。临时产物仅清理本任务已确认成功且不再需要的文件。
